# gnosys setup remote doctor

Specialized doctor mode for remote/multi-machine setups, particularly the `--ingest` flag used by automated timers (systemd, launchd, Windows Task Scheduler) to run incremental sync ingest without full interactive doctor.

## Usage

```bash
gnosys setup remote doctor --ingest --quiet
gnosys doctor --fix   # general doctor (remote doctor is a documented usage pattern)
```

## Options (for the remote doctor pattern)

- `--ingest` — Run the sync ingest sweep (used by timers to pull/push changes on schedule).
- `--quiet` — Suppress output for cron/timer runs.
- `--fix` — (via main doctor) Offer interactive cleanup of legacy artifacts.

## Behavior

- Intended for background timers on the "client" or "host" machines in a multi-machine (or network-hosted) topology.
- On Windows, users are instructed to use Task Scheduler with this command (see syncIngestTimerCommand.ts and docs).
- On Linux/macOS, systemd/launchd units are generated by `gnosys setup remote timer` / `sync-projects` that invoke this.
- The underlying logic lives in the doctor and sync ingest modules; this is the documented entry point for remote automation.

## Platform notes

### macOS
- Use with launchd (see generated plists from `gnosys setup remote timer`).
- Existing jobs may include `com.gnosys.remote-sync`.

### Linux
- systemd timer/service units generated for periodic ingest.
- `systemctl --user status` to inspect.

### Windows
- Manual Task Scheduler required (no native timer generation yet).
- Command: `gnosys setup remote doctor --ingest --quiet`.
- See syncIngestTimerCommand.ts for the exact invocation string.

## Related

- `gnosys setup remote timer` / `sync-projects` — set up the automated jobs.

## Notes

This is primarily an automation hook rather than an interactive command. Most users will never run it directly; timers do.
